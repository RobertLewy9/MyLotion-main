# 简历映射表 —— 面试官只看简历，所以按「简历上的词」来准备

> 来源：在腾讯做 Agent 开发实习的朋友的原话 ——
> 「重点就是你把项目吃透。他只会看着你简历问呀。你所有涉及到的每一个技术栈、中间件，
>  在你项目里怎么用、流程怎么样，都得吃透。然后 agent 开发就是 agent 八股。」
>
> 这条比面经的统计更硬，因为它说的是**题目从哪来**：不是从固定题库抽的，
> 而是**从你简历的字里行间长出来的**。
>
> 所以这份表的单位是**简历上的一个词**，不是知识点。

## 0. 四条铁律

1. **简历上写了的，必须能吃透；吃不透的，从简历上删掉** —— 写了答不上来是负分
2. 每个词都按三段准备：**① 在我项目里干什么 → ② 完整流程走一遍 → ③ 为什么选它、不用 X**
3. 八股多半是**顺着你简历的技术栈问的**（写了 Zustand 就问状态管理选型，写了 SSE 就问为什么不用 WebSocket）
4. 所以：**简历 = 考纲**，这份表就是考纲拆解；`面经考点.md` / `agent考点.md` 是弹药库

## 2. 每个词都要会的「三段式」话术模板

```text
① 在我项目里干什么     —— 一句话，别超过 15 个字
② 完整流程走一遍       —— 谁调用谁、数据从哪流到哪（这是区分"用过"和"懂"的地方）
③ 为什么选它 / 不用 X  —— 取舍 + 我踩过的坑
```

**照这个颗粒度自检 SSB（示例：SSE）**

- ① 我项目里 AI 的流式输出走 SSE
- ② 流程：工具在服务端执行 → 通过注入的 `onEvent` 回调把副作用塞进 `eventQueue` → SSE 包装层每 200ms 把队列取出、
  编码成 `data: <json>\n\n` 推给前端 → 前端按 `\n\n` 切行、`JSON.parse`、按 `type` 分发（渲染文本 / 显示进度 / 刷新列表 / 弹确认框）
- ③ 取舍：单向推送够用，基于 HTTP 不用协议升级，自动重连、代理友好；**要做双向协同编辑我会换 WebSocket**
