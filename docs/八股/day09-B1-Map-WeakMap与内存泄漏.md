## 思维导图

```text
对象与集合
├─ Object：字符串 / Symbol 键，适合记录字段
├─ Map：任意键、可迭代、size、频繁增删
├─ WeakMap：弱引用对象键，不可枚举，不阻止 GC
└─ 内存泄漏
   ├─ 来源：全局缓存 / 监听器 / 定时器 / 订阅 / detached DOM
   ├─ 定位：Memory 快照对比 / Allocation Timeline / 监听器数量
   └─ 修复：解绑、abort、清理、上限、弱引用
```

## Part 1 · 概念

### Q1. 普通对象、`Map`、`WeakMap` 有什么区别？

**参考答案（口述）**

| 维度 | 普通对象 | `Map` | `WeakMap` |
|------|----------|-------|-----------|
| 键类型 | 字符串 / Symbol | 任意值 | 对象（现代规范也允许非注册 Symbol） |
| 顺序 | 整数键有特殊排序 | 严格按插入顺序 | 不可迭代 |
| 大小 | `Object.keys()` 现算 | `.size` O(1) | 无 size |
| 迭代 | 可枚举自有属性 | 可 `for...of` | 不可迭代 |
| GC | 强引用键和值 | 强引用键和值 | 弱引用键，不阻止回收 |
| 典型用途 | 固定字段、配置、DTO | 频繁增删、非字符串键、LRU | 给对象附加元数据、DOM 状态缓存 |

```text
普通对象、Map 和 WeakMap 的主要区别在于键的类型、能不能遍历，以及它们对键的引用方式。

普通对象的键主要是字符串和 Symbol，适合表示结构固定的数据，比如配置、DTO。它能枚举自有属性，不过整数键的遍历顺序有特殊规则。

Map 的键可以是任意类型，包括对象；它按插入顺序迭代，也能直接通过 size 获取元素个数，所以适合需要频繁增删、查询，或者需要保留顺序的场景。

WeakMap 的键是对象，键以弱引用的方式关联：如果对象在其他地方已经没有引用，WeakMap 不会单独阻止它被垃圾回收。它不能遍历，也没有 size，因此适合给对象或 DOM 节点附加缓存、状态等元数据，但不适合需要枚举或按顺序淘汰的缓存。

所以简单来说，固定字段用对象；需要灵活键和遍历能力用 Map；数据要跟随对象生命周期、又不希望缓存留住对象时用 WeakMap。

记忆时可以抓住三句话：对象存字段，Map 管集合，WeakMap 绑对象生命周期
```

**怎么选：**

- 固定结构的数据用普通对象，类型最自然；
- 需要任意键、频繁 `has/get/set/delete`、顺序或 `.size` 用 `Map`；
- 生命周期跟随某个对象、又不想让缓存阻止对象回收，用 `WeakMap`。

如果只是用普通对象做字符串字典，又担心 `__proto__`、`constructor` 等原型键冲突，可以用 `Object.create(null)`；但需要频率统计、删除和顺序时，`Map` 更直接。

### Q2. `WeakMap` 为什么能配合 GC？有什么限制？

**参考答案（口述）**

`WeakMap` 的键是弱引用：只要外部没有其他地方再引用这个键对象，垃圾回收器就可以回收它，键对应的条目也会消失。

因此它适合：

- 给 DOM 节点保存 UI 状态；
- 给对象关联校验结果、缓存或私有元数据；
- 不想因为一张缓存表把已经废弃的对象一直留住。

限制也很明确：

- 键不能是普通字符串、数字等原始值；
- 不能遍历，没有 `size`、`keys()`、`clear()`；
- 无法知道某个对象什么时候被回收；
- 不能拿它做需要主动淘汰顺序的 LRU。

**一句话：** WeakMap 是“对象生命周期绑定的附属表”，不是通用缓存容器。

### Q3. 前端常见的内存泄漏有哪些？怎么定位？

**参考答案（口述）**

真正泄漏是：业务上已经不需要，但仍有强引用让它无法回收。

**常见来源：**

1. 全局 Map / 数组缓存无上限；
2. 事件监听器卸载时没移除；
3. `setInterval`、长定时器没清理；
4. WebSocket / SSE / 订阅没取消；
5. 闭包保存了已经不用的 DOM 或大对象；
6. detached DOM：节点已从页面移除，但仍被 JS 变量、监听器或缓存引用。

**定位方法：**

1. 用 Performance Monitor 看 JS heap 是否持续上涨；
2. 在 Memory 面板拍两次 Heap Snapshot，对比保留对象；
3. 用 Allocation Timeline 观察反复操作是否不断分配；
4. 搜 `Detached`、检查事件监听数量和对象 retaining path；
5. 固定一组“打开 → 操作 → 关闭”步骤，确认重复后仍不回落。

**修复：** React `useEffect` 返回清理函数；请求用 `AbortController`；定时器、监听器、订阅成对注册和注销；缓存设容量和失效策略；对象附属状态考虑 WeakMap。

## Part 2 · 项目落地

### Q. MyLotion 的 `DocumentCache` 为什么用 `Map` 而不是 `WeakMap`？项目里还会怎么用弱引用？

**参考答案（口述）**

`DocumentCache` 的 key 是文档 id，属于字符串，WeakMap 不能直接用；而且缓存需要：

- 知道当前 `size`；
- 按最近使用顺序做 LRU 淘汰；
- 主动遍历和清理超限条目；
- 明确失效某个 id。

这些都需要 `Map`。WeakMap 不能枚举、没有 size，也无法维护 LRU 顺序。

MyLotion 的做法是：

- `values: Map<string, T>` 存成功结果，最多 200 条；
- `pending: Map<string, Promise<T>>` 合并并发请求；
- `invalidate(id)` 在更新后清缓存；
- `fresh` 强制刷新，`prefetch` 预热但失败静默。

如果是“给某个 DOM 节点或编辑器实例附加临时状态”，生命周期天然跟着对象走、又不需要遍历，就适合 WeakMap；它不会因为这张附属表阻止节点回收。

## 30 秒复盘

普通对象适合固定字段和字符串键；Map 支持任意键、可迭代、有 size，适合频繁增删和 LRU；WeakMap 只弱引用对象键，不可枚举，不会阻止对象回收。内存泄漏的本质是无用对象仍被强引用，常见来源是全局缓存、监听器、定时器、订阅和 detached DOM。MyLotion 的文档缓存因字符串键和 LRU 需求使用 Map，而不是 WeakMap。
