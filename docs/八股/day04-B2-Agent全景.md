## 思维导图

```text
Agent 全景
├─ 输入层：Prompt + Context
├─ 决策层：LLM 决定回答或调用工具
├─ 能力层：Tool / MCP / Skill
├─ 执行层：服务端鉴权、校验、执行、回填
└─ 运行时：Agent Loop（动态） / Workflow（固定）
```

## Part 1 · 概念

### Q1. LLM、Prompt、Context 是什么关系？为什么说模型没有记忆？

**参考答案（口述）**

- **LLM**：根据输入生成文本或工具调用的模型。
- **Prompt**：给模型的指令。
- **Context**：本轮模型能看到的全部信息。

```text
Context = System Prompt + 历史/摘要 + 外部资料 + 当前输入
```

模型本身不保存会话状态。应用把历史消息存进数据库，每次请求重新拼成 Context 再交给模型。因此，“多轮对话”是应用层拼出来的记忆，不是模型内部记住了上一轮。

**一句话：** 模型负责推理，应用负责组装输入。

### Q2. Tool、Function Calling、MCP、Skill、Agent 分别在哪一层？

**参考答案（口述）**

| 名词 | 定位 |
|---|---|
| **Tool** | 具体能力，如搜索、读文档、改文档 |
| **Function Calling** | 模型用结构化格式提出“调用哪个工具、传什么参数” |
| **MCP** | Host 连接外部工具和数据源的标准协议 |
| **Skill** | 可复用的指令、知识和流程封装 |
| **Agent** | 模型决策 + 工具执行 + 结果回填组成的运行系统 |

**一次工具调用怎样发生：**

1. 应用把工具名称、用途和 JSON Schema 交给模型。
2. 模型决定是否调用，输出工具名和参数。
3. 服务端校验参数、权限和业务状态。
4. 服务端真正执行工具。
5. 工具结果作为 tool 消息回填模型。
6. 模型继续调用工具，或输出最终答复。

**关键：** 模型只做决策，不能直接访问数据库；执行、权限和副作用控制都在应用侧。

### Q3. Agent Loop 和 Workflow 有什么区别？什么时候值得用 Agent？

**参考答案（口述）**

- **Workflow**：步骤由代码预先规定，流程固定、可预测。
- **Agent Loop**：模型根据工具结果动态决定下一步。

```text
模型判断
  → 不需要工具：输出最终答案
  → 需要工具：服务端执行并回填
  → 模型继续判断，直到结束
```

**不需要 Agent：** 单次分类、改写、总结；固定步骤；单步 CRUD；对成本和延迟敏感。

**适合 Agent：** 目标开放、路径不确定、需要根据观察结果换工具或调整策略。

**工程约束：** 必须设置最大步数、超时和终止条件，防止无限循环。

## Part 2 · 项目落地

### Q. 讲清 MyLotion 的「一句话改一篇笔记」链路

**参考答案（按顺序口述）**

1. 用户输入“把 Q3 计划里的时间改成下周五”。
2. 前端 POST `/api/ai/chat`，携带 `requestId`。
3. 服务端鉴权、幂等检查，组装系统提示词、历史摘要、相关资料和当前输入。
4. `streamText` 启动 Agent Loop。
5. 模型调用 `searchNotes` 找文档，再调用 `readNote` 读取内容。
6. 服务端校验参数和 `userId`，执行工具并回填结果。
7. 模型决定调用 `updateNote`，服务端再次校验并写入数据库。
8. `onEvent` 上报修改事件，经 SSE 通知前端刷新侧边栏和编辑器。
9. 模型不再调用工具，输出最终答复。

**为什么这样分工：**

- **模型**：理解意图、选择工具，不直接操作数据库。
- **服务端**：负责权限、参数、RLS、幂等和事务。
- **前端**：接收 SSE 事件并更新 UI。
- **确认机制**：危险操作先展示影响范围，用户确认后再执行。

### 追问：只是重命名文档，还需要 Agent 吗？

不需要。目标文档已确定时，直接调用 `renameNote(id, title)` 更简单、可预测、成本更低。

**Agent 的价值是处理不确定路径，不是把所有 CRUD 都套进循环。**

## 30 秒复盘

LLM 是无状态推理模型，Prompt 是指令，Context 是应用每轮重新组装的完整输入。模型可通过 Function Calling 提出工具调用，但真正执行由服务端负责，结果再回填模型。Tool 是最小动作，MCP 负责外部能力接入，Skill 是流程封装，Agent 是动态决策和执行循环。MyLotion 用 `requestId`、鉴权、上下文组装、工具执行、SSE 事件和危险操作确认串起完整链路；固定单步任务用 Workflow 更合适。
