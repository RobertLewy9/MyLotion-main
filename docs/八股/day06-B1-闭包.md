## Part 1 · 概念

### Q1. 闭包是什么？说清“函数 + 词法环境 + 被带出作用域”

**参考答案（口述）**

闭包是函数和它定义时所在词法环境的组合。即使外层函数已经执行完，内层函数仍然能访问那个环境里的变量。

```js
function counter() {
  let n = 0;
  return function () {
    return ++n;
  };
}
const next = counter();
next(); // 1
next(); // 2
```

关键点是：**词法作用域在定义时确定，不是调用时确定。**

**常见场景：**

1. 私有变量：外部不能直接改 `n`；
2. 防抖 / 节流：保存上一次的定时器；
3. 柯里化：逐步接收参数，如 `add(1)(2)(3)`；
4. 回调保存状态：事件和定时器回调记住创建时的变量。

> 柯里化只要求会举例，不要求手写完整实现。

### Q2. 闭包为什么可能造成内存泄漏？什么才算真正泄漏？

**参考答案（口述）**

闭包会让它引用的变量在函数仍可达时继续保留，但**有闭包不等于泄漏**。

真正的泄漏是：业务上已经不需要了，但还有引用让它无法回收。

**常见三种：**

- 定时器没清：`setInterval` 回调一直挂在定时器系统上；
- 事件监听没移除：组件卸载了，监听器还挂在 `window/document`；
- 无上限缓存：Map/数组一直增长，value 又被闭包引用。

判断时问两句：**谁还引用着这个闭包？这个引用还需要吗？**

### Q3. 闭包和防抖是什么关系？为什么 `timer` 必须放在闭包里？

**参考答案（口述）**

防抖的核心就是闭包保存上一次的定时器：

```js
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

如果 `timer` 放全局，多个防抖函数会互相覆盖；放在闭包里，每个返回的函数有独立状态。

组件卸载时还应提供并调用 `cancel()`，否则定时器仍可能持有回调。

## Part 2 · 项目落地

### Q. 挑一个 MyLotion 里的闭包，按三段式讲完整

**参考答案（口述）**

#### `pendingById`：同一文档并发请求只发一次

**① 干什么：** 同一篇文档被多个组件同时请求时，只创建一个网络请求。

```js
const pendingById = new Map();

function getById(id) {
  if (pendingById.has(id)) return pendingById.get(id);

  const promise = fetchDocument(id).finally(() => {
    pendingById.delete(id);
  });
  pendingById.set(id, promise);
  return promise;
}
```

**② 流程：** 第一个调用创建 Promise 并放进 Map；后续调用复用同一个 Promise；`finally` 无论成功失败都清理。

**③ 为什么：** 去重状态需要跨组件共享，不能放在单个组件里；key 用文档 id，生命周期随请求结束而结束。

#### `debounce`：编辑器停止输入后再保存

**① 干什么：** `onChange` 触发很频繁，停止输入 300ms 后再保存。

**② 流程：** 每次输入清除上一个定时器并重新计时，用户停下后才真正请求保存接口。

**③ 为什么：** `timer` 是这份防抖函数的私有状态，不应污染全局，也不能和其他实例互相覆盖。

### 追问：状态什么时候回收？多用户请求会串吗？

- `pendingById` 的 key 是文档 id，文档本身带用户隔离；共享的是“同一篇文档的同一个请求”，不是用户私有状态。
- 如果 key 换成 `userId`，或模块级保存“当前用户草稿”，就可能串；应按请求或用户实例创建状态。
- 闭包不可达时会被回收；挂在定时器、事件监听、全局 Map 上的闭包，要等引用被清掉才回收。

## 30 秒复盘

闭包是函数与定义时词法环境的组合，让外层作用域的变量在函数执行完后仍可访问。它常用于私有变量、防抖、柯里化和回调保存状态。闭包本身不必然泄漏，真正的泄漏是业务上已不需要、但仍被定时器、监听器或缓存引用。MyLotion 用 `pendingById` 做并发去重，用 `debounce` 合并频繁保存。
