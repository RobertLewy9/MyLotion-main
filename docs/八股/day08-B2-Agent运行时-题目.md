# Day 8 · B2 轨题纸 —— Agent 运行时：循环、重试与确认闸门（面经校准版 · 20 分钟）

> **归属：Day 8 · B2 轨（Agent 八股）**
> 2026-10-29 按 8 场面经校准：面试没有要求背 ReAct 论文，也没有让你分类所有 Agent 架构；
> 真正会顺着项目追的是「一句话改一篇笔记怎么跑起来」「工具失败怎么办」「删错了怎么办」。
> 承接 Day 6 的 Tool Calling，今天只准备 **3 个概念 + 1 个项目落地**，不重复 LLM 基础与 MCP 概览。

## Part 1 · 概念口述（每题 2 分钟）

**1.** 一次普通模型调用和 Agent Loop 有什么区别？
Agent Loop 靠什么继续、靠什么停止？工程上怎样防止它无限调用工具或成本失控？

**2.** 工具执行失败、超时，或者被重复调用时怎么处理？
哪些错误应该回填给模型，哪些必须直接终止？为什么写操作调用前要先做幂等设计？

**3.** `deleteNote` 这种不可逆工具，为什么不能由模型直接执行？
用 human-in-the-loop 设计一个「先预览、再确认、最后只执行一次」的流程。

## Part 2 · 项目落地（必答）

按「① 我项目里干什么 → ② 完整流程 → ③ 为什么这样设计」讲清 MyLotion 的 Agent 主链路：

- 前端带 `requestId` 请求 `/api/ai/chat`；
- 服务端鉴权、防重复、组装上下文；
- `streamText` 驱动 Agent Loop，模型选择 7 个工具之一；
- 工具在服务端校验参数和 `userId` 后执行，结果回填模型；
- 有副作用的操作通过 `onEvent` 上报，再经 SSE 推给前端；
- `deleteNote` 第一次只返回 `confirm_delete`，用户确认后才真正删除。

> 追问预判：如果用户连续点两次发送，怎样保证只产生一次 Agent 运行？如果确认框被重复点击，怎样避免删两次？

## 自测标准

- 能说清 Agent Loop 的「模型决定 → 服务端执行 → 结果回填」循环；
- 能区分可恢复错误、权限错误和幂等重试；
- 能讲明白危险工具为什么必须由服务端做最终把关；
- 能在 2 分钟内按顺序讲完 MyLotion 的 AI 主链路。
