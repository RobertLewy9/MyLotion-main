> **归属：Day 6 · B2 轨（Agent 八股）**

## 1. tool / skill / subagent / agent 的区别

| 概念 | 一句话解释 | 谁在执行 |
|------|------------|----------|
| **tool** | 一个具体能力，例如“搜索笔记”“读取文档”，有名字、描述和参数 schema | 应用服务端执行 |
| **skill** | 一组可复用的指令、知识和流程封装，告诉模型“遇到这类任务该怎么做” | 通常由宿主/平台加载，可能调用多个 tool |
| **subagent** | 被主 Agent 委派出去处理子任务的独立 Agent，有自己的上下文和工具集合 | 独立的 Agent 循环 |
| **agent** | 能根据目标和观察结果决定下一步、调用工具并继续执行的系统 | 模型 + 运行时共同完成 |

关系可以这样记：**Agent 做决策，tool 是最小执行单元，skill 是做事方法的封装，subagent 是拆出去的另一个执行者。**

MyLotion 里七个搜索/读写/归档工具属于 tool；如果把这些工具组合成“整理一篇笔记”的固定流程，可以封装成 skill；
本项目的规模不需要多 Agent，所以没有拆 subagent。

## 2. MCP 和 Function Calling 的关系

**MCP（Model Context Protocol）** 是一套让模型应用连接外部工具和数据源的协议；
**Function Calling** 是模型输出“我要调哪个函数、参数是什么”的机制。

一句话区分：
- **Function Calling 管怎么调**：模型产出结构化工具调用；
- **MCP 管怎么接**：宿主通过标准协议发现并连接工具服务器，把外部能力暴露给模型。

MCP 不取代 Function Calling。模型仍然通过工具调用表达意图，MCP 负责工具从哪里来、怎么被发现和连接。

## 3. 工具调用是谁执行？结果怎么回填？

模型只负责**决定工具名和参数**；真正执行的是应用服务端。
执行完把结果作为 tool 消息（或对应的工具结果）回填到下一轮模型上下文，模型再决定继续调用还是给出最终答复。

这也意味着两件事：
1. 参数必须校验，尤其是文档 id 和 `userId`；
2. 工具执行不是模型内部行为，权限、超时和幂等都要由服务端负责。

## 4. 为什么工具调用优于模型直接吐整篇内容？

模型直接输出一大段内容，应用只能把它当普通文本，无法只改一个字段，也难以校验、授权、审计和回滚。
工具调用把操作收敛成 `readNote(id)`、`updateNote(id, patch)` 这样的**可校验最小操作**：
- 服务端可以检查参数和用户归属；
- 危险操作可以加确认闸门；
- 失败可以重试或把错误反馈给模型；
- 副作用可以显式上报给前端。

## Part 2 · MyLotion 的完整链路

1. 用户输入进入 `/api/ai/chat`，服务端鉴权并组装上下文；
2. 模型返回 `searchNotes` 或 `readNote` 等工具调用；
3. 服务端按 schema 校验参数，带 `userId` 查询数据库并执行；
4. 工具结果回填给模型，模型继续下一步或生成最终回答；
5. 有副作用的工具通过 `onEvent` 上报 `note_modified` 等事件，经 SSE 推给前端；
6. 前端按事件类型刷新侧边栏、显示进度或弹出删除确认。

**工具报错怎么处理？** 可恢复错误（参数不对、目标不存在）整理成错误结果回给模型，让它换参数或换工具；
权限拒绝等不可恢复错误直接终止该操作，并记录日志，不能让模型无限重试。
