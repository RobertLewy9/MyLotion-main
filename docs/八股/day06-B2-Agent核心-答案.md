# Day 6 · B2 答案 —— Agent 核心：ReAct 与停止条件（口述版）

> **归属：Day 6 · B2 轨（Agent 八股）**
> 答法统一：**一句话结论 → 展开为什么 → 落回 MyLotion**。

## 1. Agent 和「一次模型调用」的区别？Agent 和 workflow 的区别？

**一句话**：一次调用是「输入 → 输出」；Agent 是「模型在循环里自己决定下一步」；
workflow 是「路径由代码写死，模型只在节点上做判断」。

**展开**：
- **一次调用**：模型不改变外部世界，只产出文本。
- **Agent**：模型可以调工具、看结果、再决定下一步，**循环几次、走哪条路，由模型决定**。
- **Workflow**：步骤是代码编排好的（取数 → 分类 → 生成 → 审核），模型只是其中几个节点。

**区别就一句话：控制权在模型还是代码。** Agent 灵活但不确定，workflow 稳定但覆盖不了开放场景。
生产里常见的是「workflow 骨架 + 某个节点交给 agent」，而不是纯 agent。

**落回 MyLotion**：用户说「帮我找性能优化的笔记并归档」，模型可能先搜、再读、再归档，
也可能搜完发现没有就直接回答 —— 这个路径不是我写死的，所以它是 agent，不是 workflow。

## 2. ReAct 的循环是什么？为什么「观察」不能省？

**一句话**：**Reason（想）→ Act（调工具）→ Observe（看结果）**，循环直到满足停止条件。

**展开**：
- **Reason**：根据目标和已经看到的结果，决定下一步做什么、要不要调工具、调哪个、参数是什么。
- **Act**：输出一次工具调用（tool call）。
- **Observe**：服务端执行工具，把**真实结果**回填进上下文。

**为什么不能省观察**：模型没有「执行」能力，它只能基于上下文推理。没有观察，它就是在**闭卷猜**——
会编造「我已经找到了」「已经删掉了」。观察就是环境反馈，是把模型从幻觉拉回现实的唯一手段。

## 3. Agent loop 的停止条件有哪些？只设步数上限够不够？

**一句话**：至少四类 —— 不再调工具、步数上限、命中终止工具、外部中断（超时 / abort）。

**展开**：
1. **模型不再发起 tool call**，返回纯文本 → 正常结束；
2. **步数上限**（`stopWhen` / `maxSteps`）→ 防止来回调工具停不下来；
3. **命中终止工具**（如 `finish` / `submit`）→ 业务上明确「做完了」；
4. **超时 / 用户 abort / token 预算耗尽** → 外部兜底。

**只设步数上限不够**，因为它只防「次数」，不防「质量」：
- 模型可能连续 5 步调同一个工具、参数都一样（原地打转）；
- 每步都「成功」，但目标没达成（搜到了却没归档）；
- 工具一直超时，5 步全耗在重试上。

所以还要：重复调用检测、工具级超时、结果校验、危险操作的人机确认。

**落回 MyLotion**：`stopWhen` 5 步 + 每个工具 30s 显式超时 + 删除操作走确认闸门，三层一起兜。

## 4. MyLotion 的 `streamText({ model, tools, stopWhen })` 怎么落地 ReAct？

**① 在我项目里干什么**：它是整个 Agent 循环的驱动器 —— 模型想、调工具、看结果，都由它串起来。

**② 完整流程**：
- 服务端把 `[系统提示词 + 历史摘要 + 最近 100 条 + 当前输入]` 和 7 个工具的 schema 一起传给 `streamText`；
- 模型第一轮输出一个 tool call，比如 `searchNotes({ query: "性能优化" })`；
- SDK 执行这个工具（**在服务端**），把返回值作为一条 tool 消息追加进上下文；
- 模型基于新上下文继续，第二轮调 `archiveNote({ id })`；
- 工具内部通过 `onEvent` 上报 `note_modified`，SSE 推给前端；
- 模型不再调工具、返回文本，或者到 5 步上限 → 循环结束。

**③ 为什么用 SDK 而不是自己写 `while`**：我自己写要处理流式增量、tool call 的拼装、消息格式、错误回传、abort；
SDK 把这些协议细节都封装了，我只负责「给工具、给刹车、处理副作用」。**但刹车必须是我显式给的**——
SDK 不会替你决定几步算多。

## 追问预判

**模型连续三次调同一个工具、参数还一样？**
先看工具是否幂等；然后在循环层做「相同 tool + 相同参数」的重复检测，第二次就回一条提示性错误
（「你已经查过了，结果是 …」），逼它换策略；再不行就停。

**工具报错，抛给前端还是回传给模型？**
回传给模型，但**转成可读的错误字符串**（`withToolLogging` 做的就是这件事），让它自己决定重试还是换路；
同时记录日志。直接把异常抛给前端，等于让用户看栈，而且这一轮 Agent 也白跑了。

## 三条金句

1. **「Agent 和 workflow 的区别，就是控制权在模型还是代码。」**
2. **「没有 Observe，模型就是在闭卷猜。」**
3. **「步数上限只防次数，不防原地打转 —— 刹车要有多层。」**
