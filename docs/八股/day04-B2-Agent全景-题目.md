# Day 4 · B2 轨题纸 —— Agent 全景与一次请求链路（面经校准版 · 20 分钟）

> **归属：Day 4 · B2 轨（Agent 八股）**
> 2026-11-04 回补：8 场面经真正问过的是 Token / 上下文、`tool / skill / subagent / agent`、MCP 和项目链路。
> Day 4 不深挖这些专题，只先建立一张地图：**模型在哪里、应用做了什么、工具和 Agent 各处在哪一层**。
> 保持 **3 个概念 + 1 个项目落地**，后面 Day 5–8 再分别展开。

## Part 1 · 概念口述（每题 2 分钟）

**1.** LLM、Prompt、Context 三者是什么关系？
为什么说模型本身没有记忆，多轮对话其实是应用每次重新组装输入？

**2.** Tool、Function Calling、MCP、Skill、Agent 分别在哪一层？
模型调用工具时，谁负责决策、谁负责真正执行、结果又怎样回到模型？

**3.** Agent Loop 和 Workflow 有什么区别？
什么任务一次模型调用就够，什么任务才值得让 Agent 循环调用工具？

## Part 2 · 项目落地（必答）

按「① 用户做什么 → ② 请求经过哪些层 → ③ 为什么这样分工」讲清 MyLotion 的「一句话改一篇笔记」：

- 用户输入一句话，前端发到 `/api/ai/chat`；
- 服务端鉴权、组装上下文并调用模型；
- 模型决定调用哪个工具和参数，服务端校验 `userId` 后执行；
- 工具结果回填模型，模型继续判断或给出最终答复；
- 有副作用的操作通过 `onEvent` + SSE 通知前端；
- 危险操作先弹确认，不直接执行。

> 追问预判：如果只是把一篇笔记重命名，还需要让 Agent 自由决策吗？为什么？

## 自测标准

- 能画出「用户 → 应用 → 模型 → 工具 → 模型 → 用户」的主链路；
- 能说清模型只做决策，工具执行和权限控制都在应用侧；
- 能区分 Workflow 与 Agent Loop；
- 能在 2 分钟内讲完 MyLotion 的 AI 请求链路。
