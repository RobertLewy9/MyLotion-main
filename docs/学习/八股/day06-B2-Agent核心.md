# Day 6 · B2 轨 —— Agent 词汇与 Tool Calling（问答一体）

> **归属：Day 6 · B2 轨（Agent 八股）**
> 依据：携程一面、腾讯云智一面实际问过 `skills`、`MCP`、`tool / skill / subagent / agent` 的区别。
> 用法：先能用一句话辨析概念，再用 MyLotion 主链路证明你真的做过。

## 思维导图

```text
Agent 词汇与 Tool Calling
├─ tool：最小可执行能力
├─ skill：做事方法的封装，可调用多个 tool
├─ subagent：独立上下文和工具集的另一个 Agent
├─ agent：模型决策 + 工具执行 + 结果回填
├─ MCP：外部能力的标准接入协议
└─ Function Calling：模型表达“我要调用什么”
```

## Part 1 · 概念

### Q1. `tool`、`skill`、`subagent`、`agent` 分别是什么？关系是什么？

**参考答案（口述）**

| 概念 | 一句话解释 | 谁在执行 |
|---|---|---|
| **tool** | 具体能力，如搜索笔记、读取文档；有名称、描述和参数 schema | 应用服务端 |
| **skill** | 一组可复用的指令、知识和流程封装，告诉模型“这类任务怎么做” | 宿主/平台加载，可调用多个 tool |
| **subagent** | 被主 Agent 委派处理子任务的独立 Agent，有自己的上下文和工具集合 | 独立 Agent 循环 |
| **agent** | 根据目标和观察结果决定下一步、调用工具并继续执行的系统 | 模型 + 运行时 |

**关系记忆：** Agent 做决策，tool 是最小执行单元，skill 是做事方法，subagent 是拆出去的另一个执行者。

MyLotion 的搜索、读写、归档工具属于 tool；“整理一篇笔记”的固定流程可以封装成 skill；当前规模不需要拆 subagent。

### Q2. MCP 是什么？它和 Function Calling 是什么关系？

**参考答案（口述）**

- **MCP（Model Context Protocol）**：让 AI 应用用统一方式连接外部工具、数据源和提示模板的协议。
- **Function Calling**：模型输出“调用哪个函数、参数是什么”的机制。

**一句话区分：**

- **Function Calling 管怎么调**：模型产出结构化工具调用；
- **MCP 管怎么接**：Host 通过标准协议发现并连接工具服务器。

MCP 不取代 Function Calling。模型仍通过工具调用表达意图，MCP 负责这些工具从哪里来、如何被发现和连接。

### Q3. 模型调用工具时，谁决定、谁执行？结果怎么回填？

**参考答案（口述）**

1. 模型只负责决定**工具名和参数**。
2. 应用服务端校验参数、权限、超时和用户归属。
3. 服务端真正执行工具。
4. 结果作为 tool 消息回填下一轮模型上下文。
5. 模型继续调用工具，或输出最终答复。

**关键：** 工具执行不是模型内部行为，权限、幂等和副作用控制都必须由服务端负责。

### Q4. MyLotion 有 19 个工具，为什么不让模型直接输出一整篇笔记？

**参考答案（口述）**

模型直接输出一大段文本，应用只能把它当普通文本，无法只改一个字段，也难以校验、授权、审计和回滚。

工具调用把操作收敛成 `readNote(id)`、`updateNote(id, patch)` 这样的**可校验最小操作**：

- 服务端检查参数和用户归属；
- 危险操作可以加确认闸门；
- 失败可以重试或回填模型；
- 副作用可以显式上报给前端。

## Part 2 · 项目落地

### Q. 按“① 我项目里干什么 → ② 完整流程 → ③ 为什么不用 X”讲清 MyLotion 的 Tool Calling

**参考答案（口述）**

**① 我项目里干什么：** 用户用自然语言搜索、读取、修改和归档文档，模型不直接访问数据库，而是从 19 个受控工具中选择动作。

**② 完整流程：**

1. 用户输入进入 `/api/ai/chat`，服务端鉴权并组装上下文。
2. 模型返回 `searchNotes` 或 `readNote` 等工具调用。
3. 服务端按 schema 校验参数，带 `userId` 查询数据库并执行。
4. 工具结果回填给模型，模型继续下一步或生成最终回答。
5. 有副作用的工具通过 `onEvent` 上报 `note_modified` 等事件，经 SSE 推给前端。
6. 前端按事件类型刷新侧边栏、显示进度或弹出删除确认。

**③ 为什么不让模型直接输出内容或 SQL：**

- 模型无法直接拿到数据库权限，避免越权；
- 参数和用户归属能在服务端统一校验；
- 失败、重试、幂等和审计有明确落点；
- 前端能通过结构化事件感知副作用。

### 追问：工具报错时，抛给前端还是反馈给模型？

可恢复错误（参数不对、目标不存在）整理成错误结果回给模型，让它换参数或换工具；权限拒绝等不可恢复错误直接终止该操作并记录日志，不能让模型无限重试。

## 30 秒复盘

tool 是最小能力，skill 是流程封装，subagent 是独立执行者，agent 是完整运行系统。Function Calling 负责“怎么调”，MCP 负责“怎么接”。MyLotion 中模型决定工具名和参数，服务端校验并执行，结果回填模型，副作用经 `onEvent` 和 SSE 通知前端。
