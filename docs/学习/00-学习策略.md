> **归属：元文档（学习策略）**
> 依据：8 场面经（B站 / CSIG / IEG / 快手一面 / 快手二面 / 携程 / 腾讯云智一面 / 腾讯云智二面）+ 腾讯 Agent 开发实习反馈。
> 目标：前端 / Agent 开发方向实习 offer。Lotion 是简历上的主项目。

## 一、面经给出的真实比例

| 类型 | 大致占比 | 典型问题 |
|---|---:|---|
| 前端 / 计算机八股 | ~60% | 事件循环、闭包、原型、hooks、缓存、跨域、JWT vs Session |
| 项目深挖 | ~30% | 为什么用这个组件？为什么不用 X？规模变大怎么办？ |
| 手撕代码 | ~10% | 力扣算法、少量前端工程题 |

**结论：项目不是让你复述源码，而是考技术决策；手撕主要靠力扣，不靠重写业务函数。**

## 二、从“会写代码”切换到“会做选型”

项目已经有完整实现，当前最重要的不是再写一遍，而是把每个重要依赖讲成一条决策链：

```text
业务 / 部署约束
  → 候选方案
  → 选择理由
  → 代价与边界
  → 什么时候换掉
```

例如 SQLite：

> 项目定位是单机自托管，数据量是个人笔记，部署要零外部服务，所以选 SQLite + better-sqlite3，WAL 保证读写并发，启动自动迁移。代价是没有 RLS、不能多实例写入，所有查询必须显式带 `userId`。如果以后公网多实例部署，我会换 PostgreSQL 或远程 libSQL。

这比背 `lib/local/db.ts` 里每个函数更有面试价值。

## 三、A / B / C 三条轨

| 轨 | 每天时间 | 学什么 | 产出 |
|---|---:|---|---|
| **A · 技术选型** | 45min | 组件职责、选型理由、替代方案、边界 | 五问选型卡 + 2 分钟口述 |

## 四、A 轨怎么学

### 每天固定五问

1. **它是什么**：一句话，不用官网介绍。
2. **在项目里干什么**：入口、调用方向、落点。
3. **为什么选它**：先说业务和部署约束，再说能力。
4. **替代方案**：至少两个，各说一个优势和一个代价。
5. **什么时候换**：给业务、规模、团队或部署触发条件。

### 三条纪律

- **不读业务函数级实现**：只看架构入口、依赖关系和官方定位。
- **不把“性能好”当理由**：要说明为什么这个项目的约束需要它。
- **每题必须有反例**：只会说为什么用，不会说什么时候不用，等于没吃透。

### 读哪些材料

| 材料 | 用法 |
|---|---|
| `docs/学习/A-技术选型总览.md` | A 轨主教材，按天查对应选型 |
| `docs/学习/A-架构总览.md` | 看组件如何串成主链路 |
| `AGENTS.md`、`docs/项目/插件化架构.md`、`docs/项目/本地数据库版.md` | 核对真实约束和边界，不做源码逐行阅读 |
| `README.md` | 技术栈与运行方式的一手说明 |

## 五、B 轨怎么学

- B1 与 B2 每天各推进一组，复盘日混合抽错题。
- 每题三步：**结论 → 机制 → 项目落点**。
- 项目落点优先选择简历上出现的词：SSE、Tool Calling、Zustand、BlockNote、SQLite、Session。
- 不默写长答案；用 30 秒能讲清的结构，再看细节。

## 六、C 轨怎么学

- **直接在力扣官网刷 Hot 100**；项目业务函数和本地测试不再纳入 C 轨。
- 不再生成每日 C 题解 md；唯一进度入口是 `docs/学习/C-力扣Hot100题单.md`。
- 每题 20 分钟，先写再对照；记录错因、复杂度和一个可迁移的模式。
- 首刷后隔两天闭卷重写；复盘日只重写错题。
- 前端手撕题（数组拍平、EventEmitter、图片懒加载）只要求会讲思路，遇到再补，不占每日时间。
- 目标不是 100/100，而是高频题能独立 AC、错题能闭卷复写。

## 七、简历即考纲

面试官通常顺着简历问，所以准备单位是“简历上的一个词”，不是知识点。

### 四条铁律

1. **写了必须吃透，吃不透就删。**
2. 每个词按三段式：**① 干什么 → ② 完整流程 → ③ 为什么选它、不用 X。**
3. 八股顺着技术栈问：写了 SSE 就问 WebSocket；写了 SQLite 就问 PostgreSQL；写了 Zustand 就问 Redux。
4. 第 ② 步是分水岭：能说清数据从哪来、经过谁、落到哪，才像真做过。

### 日常动作

| 频率 | 动作 |
|---|---|
| 每天 | A 轨最后 2 分钟，挑一个简历词脱稿讲 |
| 每天 | B 轨项目题优先选简历上出现过的词 |
| 复盘日 | 抽 6 个最不稳的词，录音回听 |
| Day 47 | 简历逐词定稿：讲不满的词补上或删掉 |

逐词映射见 `docs/面试/全轨-简历映射.md`。

## 八、每天怎么用

1. **开场 5 分钟**：复述昨天 A/B/C 各一个结论。
2. **A 45 分钟**：读选型卡 → 填五问 → 录音 2 分钟 → 接一个换场景追问。
3. **B 30 分钟**：B1 15 分钟 + B2 15 分钟，各 1 回炉 + 1-2 新题 + 1 个项目落点。
4. **C 40 分钟**：去力扣官网刷 1-2 题，回来只更新 Hot 100 总表。
5. **收尾 5 分钟**：日志写 3 个成功 + 1 个明天的难度增量。

## 九、项目边界要提前准备

面试官常问“数据量再大怎么办”。固定答法：

1. **先承认当前边界**：单机 SQLite、单进程、单篇 JSON、个人规模。
2. **分三层说瓶颈**：存储、网络、渲染/交互。
3. **给演进路径**：PostgreSQL/远程 libSQL、对象存储、分块/CRDT、虚拟化、全文检索。
4. **给产品兜底**：阈值提示、拆子文档、限流、降级。

不要说“能扛”，也不要说“不能扛”；要说“现在靠什么扛，什么时候必须换”。

## 十、当前阶段的取舍

- 项目代码已经完整，**不再以写代码和跑测试为主线**。
- A 轨优先覆盖：Vite/Next、SQLite/Postgres、Session/JWT、SSE/WebSocket、BlockNote/Tiptap、AI SDK/LangChain、Hono/Express、Cordis/单体。
- B 轨只保留高频八股和项目落点。
- C 轨只练力扣，保证面试现场能写出来。
- 复盘日只做迁移，不整卷重刷。

> 一句话：**把“我实现了什么”换成“我为什么这样选、代价是什么、什么时候换”。**
