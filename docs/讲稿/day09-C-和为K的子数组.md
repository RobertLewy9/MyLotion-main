# Day 9 · C 轨题解 —— 和为 K 的子数组（Hot 100 · 前缀和）

> **归属：Day 9 · C 轨（力扣 / 手撕）**
> 题目文件：`src/interview/subarray-sum.ts`；用例：`test/interview/subarray-sum.test.ts`（7 个）。
> **先自己限时 20 分钟写，再往下看。** 目标复杂度 O(n)，注意数组里可能有负数。

## 一、题目

给定整数数组 `nums` 和整数 `k`，返回和恰好为 `k` 的**连续子数组**个数。

```text
输入: nums = [1,1,1], k = 2
输出: 2
解释: [1,1] 有两种起止位置

输入: nums = [1,2,3], k = 3
输出: 2
解释: [1,2] 和 [3]

输入: nums = [1,-1,0], k = 0
输出: 3
```

## 二、思路演化（面试时就这么讲）

**第一层：枚举左右端点。**

固定起点，向右累加并检查是否等于 `k`，时间 O(n²)。这是保底解法。

**第二层：前缀和 + 哈希表。**

令 `prefix[i]` 表示前 `i` 个元素的和。区间 `(j, i]` 的和为：

```text
prefix[i] - prefix[j] = k
```

也就是在扫描到 `i` 时，查找之前有多少个前缀和等于 `prefix[i] - k`。

**第三层：边扫边存，省掉前缀和数组。**

维护当前前缀和 `prefix` 和哈希表 `count`：键是出现过的前缀和，值是该前缀和出现的次数。每扫一个数：

```text
prefix += nums[i]
答案 += count[prefix - k]
count[prefix]++
```

初始化必须写 `count.set(0, 1)`，表示“空前缀和为 0”。否则从数组开头开始的子数组会被漏掉。

## 三、参考实现

```ts
export function subarraySum(nums: number[], k: number): number {
  const count = new Map<number, number>();
  count.set(0, 1);

  let prefix = 0;
  let answer = 0;

  for (const num of nums) {
    prefix += num;
    answer += count.get(prefix - k) ?? 0;
    count.set(prefix, (count.get(prefix) ?? 0) + 1);
  }

  return answer;
}
```

关键顺序：**先查旧前缀和，再把当前前缀和加入表**。如果先加入自己，`k = 0` 时会把长度为 0 的区间错误算进去。

## 四、复杂度

- 时间：**O(n)**。每个元素只扫描一次，哈希表平均 O(1) 查询和插入。
- 空间：**O(n)**。最坏情况下每个前缀和都不同。

## 五、易错点

1. **忘记 `count.set(0, 1)`**：会漏掉从下标 0 开始的子数组。
2. **先插入再查询**：会把当前元素自己当成“之前出现过”，导致错误。
3. **用滑动窗口**：数组含负数时，右移窗口不保证和单调增加，左指针无法安全收缩。
4. **只记前缀和是否存在**：本题问的是个数，必须记录每个前缀和出现的次数。
5. **哈希表覆盖旧次数**：先查 `prefix - k`，再用累加方式更新 `prefix` 的频次。
6. **大整数精度**：普通整数范围内用 `number` 没问题；若题目允许超过安全整数，需要改用 `BigInt` 或专门的大数方案。

## 六、面试追问

**Q1：为什么负数会让滑动窗口失效？**

窗口右移时和不一定增大，窗口左移时和也不一定减小，无法用“和太大就缩左边界”的单调性保证不漏解。

**Q2：空间能不能优化？**

如果只判断是否存在一个子数组，可以用集合；但题目要求个数，必须保存频次。最坏仍需要 O(n) 个不同前缀和。

**Q3：如果要求返回所有子数组本身，而不只是数量？**

哈希表里存“前缀和 → 下标列表”，每个当前下标与列表中的历史下标组合，就能还原区间；输出规模本身可能达到 O(n²)，无法优于输出量。
