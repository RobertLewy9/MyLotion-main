# Day 6 · C 轨题解 —— 最长连续序列（Hot 100 · 哈希）

> **归属：Day 6 · C 轨（力扣 / 手撕）**
> 题目文件：`src/interview/longest-consecutive.ts`；用例：`test/interview/longest-consecutive.test.ts`（8 个）。
> **先自己限时 20 分钟写，再往下看。** 目标复杂度 O(n)。

## 一、题目

给定未排序的整数数组 `nums`，返回**最长连续序列**的长度。
「连续」指数值连续（1,2,3…），**不要求元素在数组里相邻**。

```text
输入: [100, 4, 200, 1, 3, 2]
输出: 4          // 1,2,3,4
```

## 二、思路演化（面试时就这么讲）

**第一层：暴力** —— 对每个数，while 找 `n+1` 在不在数组里。
每个数都要线性查找，最坏 `O(n²)`；而且同一个序列会被重复数很多遍。

**第二层：排序** —— 先排序再扫一遍，`O(n log n)`。
能过，但不是最优；面试官问「还能更快吗」就是让你往哈希走。

**第三层：哈希集合** —— 把所有数放进 `Set`，查找变 `O(1)`。
关键优化：**只从「序列起点」开始数** —— 如果 `n - 1` 也在集合里，说明 `n` 不是起点，直接跳过。
这样每个元素最多被访问两次（一次判断起点、一次在某个序列里被数到），总体 `O(n)`。

## 三、参考实现

```ts
export function longestConsecutive(nums: number[]): number {
  const set = new Set(nums);
  let best = 0;

  for (const n of set) {
    if (set.has(n - 1)) continue; // 不是起点，跳过

    let length = 1;
    while (set.has(n + length)) length++;
    if (length > best) best = length;
  }

  return best;
}
```

## 四、复杂度

- 时间：**O(n)**（平均）。`Set` 的 `has` 是 O(1)；外层遍历 n 次，内层 `while` 只在起点触发，
  整条序列的元素总共只会被数一次。
- 空间：**O(n)**，存 `Set`（顺便去重）。

## 五、易错点

1. **忘了去重**：`[1,2,0,1]` 里重复的 1 不能让长度多算。
2. **从每个数都开始数**：那就退化成 O(n²)，性能用例（10 万）会挂。
3. **空数组**：直接返回 0，`Set` 为空时循环不执行。
4. **负数**：逻辑不受影响，但别写 `n > 0` 这种想当然的剪枝。

## 六、面试追问

**Q1：为什么 `if (set.has(n - 1)) continue;` 能保证 O(n)？**
因为它保证每个连续段**只从最小元素开始数一次**；段内其他元素在遍历时直接跳过，
而段内每个元素在 `while` 里最多被访问一次，所以总访问量是线性的。

**Q2：如果要求返回这个序列本身，而不只是长度？**
起点已经确定了，`while` 里把值收进数组即可；复杂度不变（返回本身需要 O(k) 空间）。

**Q3：数据是流式到达的，不能全存内存怎么办？**
那就不能保证精确 O(n) 了。工程上退一步：用哈希分桶 + 每桶维护区间端点，或者接受近似/外部排序。
面试里答「先承认内存约束，再给分桶或外部排序」就够。
