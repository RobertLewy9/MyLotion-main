# Day 10 · C 轨题解 —— 滑动窗口最大值（Hot 100 · 单调队列）

> **归属：Day 10 · C 轨（力扣 / 手撕）**
> 题目文件：`src/interview/sliding-window-maximum.ts`；用例：`test/interview/sliding-window-maximum.test.ts`（7 个）。
> **先自己限时 20 分钟写，再往下看。** 目标复杂度 O(n)。

## 一、题目

给定数组 `nums` 和窗口大小 `k`，窗口每次向右移动一格，返回每个窗口中的最大值。

```text
输入: nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
输出: [3, 3, 5, 5, 6, 7]

窗口依次为：
[1  3 -1] -3  5  3  6  7   → 3
 1 [3 -1 -3] 5  3  6  7   → 3
 1  3 [-1 -3 5] 3  6  7   → 5
 1  3 -1 [-3 5 3] 6  7   → 5
 1  3 -1 -3 [5 3 6] 7   → 6
 1  3 -1 -3  5 [3 6 7]  → 7
```

## 二、思路演化（面试时就这么讲）

**第一层：每个窗口扫一遍。**

窗口有 `n - k + 1` 个，每个窗口扫 `k` 个元素，时间 O(nk)。`k` 接近 `n` 时会退化成 O(n²)。

**第二层：大根堆。**

把窗口元素放进堆，堆顶是最大值，时间 O(n log k)。可行，但还要处理堆里已经滑出窗口的过期元素。

**第三层：单调队列。**

队列里只保留“可能成为窗口最大值”的下标，并让它们的值从队头到队尾单调递减：

- 队头就是当前窗口最大值；
- 新元素进来时，把队尾所有不大于它的元素弹掉，因为它们不可能再当最大值；
- 窗口左端滑出时，如果队头下标过期，就从队头移除。

每个下标最多入队一次、出队一次，所以时间是 O(n)。

## 三、单调队列的不变量

```text
队列中存的是下标，不是值
nums[deque[0]] >= nums[deque[1]] >= ... >= nums[deque[last]]
deque 中的所有下标都在当前窗口内
```

为什么存下标？因为只存值无法判断它有没有滑出窗口。下标既能在 `nums` 中取值，也能和 `right - k + 1` 比较。

为什么可以弹掉队尾较小值？当前新值更大、且更晚过期；以后窗口里的最大值不可能轮到那些较小值。

## 四、参考实现

```ts
export function maxSlidingWindow(nums: number[], k: number): number[] {
  if (nums.length === 0 || k <= 0) return [];

  const deque: number[] = [];
  const result: number[] = [];

  for (let right = 0; right < nums.length; right++) {
    while (deque.length > 0 && deque[0] < right - k + 1) {
      deque.shift();
    }

    while (
      deque.length > 0 &&
      nums[deque[deque.length - 1]] <= nums[right]
    ) {
      deque.pop();
    }

    deque.push(right);

    if (right >= k - 1) {
      result.push(nums[deque[0]]);
    }
  }

  return result;
}
```

执行顺序：先清理过期下标，再维护单调性，再加入当前下标，最后在窗口形成后记录答案。

## 五、走一遍标准用例

```text
right=0, num=1: deque=[0]
right=1, num=3: 1<=3，弹出 0；deque=[1]
right=2, num=-1: deque=[1,2]；窗口形成，答案 nums[1]=3
right=3, num=-3: deque=[1,2,3]；答案仍是 3
right=4, num=5: 弹出 3、2、1；deque=[4]；答案 5
right=5, num=3: deque=[4,5]；答案 5
right=6, num=6: 弹出 5、4；deque=[6]；答案 6
right=7, num=7: 弹出 6；deque=[7]；答案 7
```

## 六、复杂度

- 时间：每个下标最多进入一次、离开一次，**O(n)**；
- 空间：队列最多同时保留 k 个下标，**O(k)**；
- 结果数组不计入辅助空间。

> JS 的数组 `shift()` 理论上有元素搬移成本。面试里通常按双端队列 O(1) 讲；如果面试官追问 JS 实现细节，可以改用头指针或手写链表实现严格 O(1) 的双端操作。

## 七、易错点

1. **存值而不是下标**：无法判断是否滑出窗口。
2. **先记录答案再维护队列**：会把旧最大值带进新窗口。
3. **弹队尾用 `<` 还是 `<=`**：用 `<=` 可以去掉等值旧元素，避免队列里堆积无用候选；用 `<` 也不会错，但队列更长。
4. **过期判断写成 `<= right - k` 或 `< right - k`**：窗口是 `[right-k+1, right]`，下标小于 `right-k+1` 才过期。
5. **`k` 大于数组长度**：上面的实现不会形成窗口，返回 `[]`；如果题目保证 `1 <= k <= n`，可以省略这层兜底。

## 八、面试追问

**Q1：为什么时间复杂度是 O(n)，不是 O(nk)？**

外层 `right` 走 n 次；内层虽然是 `while`，但每个下标最多被 `push` 一次、被 `pop` 或 `shift` 一次，总操作次数是线性的。

**Q2：为什么队列里的值要递减？**

如果后面的元素比前面大，前面的元素既更小又更早过期，不可能再成为任何未来窗口的最大值，所以可以安全删除。

**Q3：如果数据是流式的，不能保存整个数组？**

单调队列天然适合流式处理：只保留当前窗口内的下标；需要一个能按时间淘汰的队列和当前窗口编号，空间仍是 O(k)。

**Q4：和优先队列方案怎么选？**

堆实现更直观，但 O(n log k) 且要处理懒删除；单调队列是这题的更优解，适合面试展示对“过期”和“单调性”的理解。
