## 一、先看数据：面试到底考什么

把 8 场面经的题目（去重后）按类型粗分：

| 类型 | 占比 | 典型题 |
|------|------|--------|
| 前端 / 计算机八股 | ~60% | 事件循环、闭包、跨域、强缓存 + hash、cookies/localStorage、重绘重排、hooks 原理、Zustand 选型、JWT vs session、进程线程、SSR / FCP / LCP |
| 项目深挖 | ~30% | CRDT vs OT、SSE vs WebSocket、无限层级懒加载、权限设计、状态分区、性能优化、Convex、BlockNote |
| 手撕代码 | ~10% | 有效的括号、数组拍平、EventEmitter、字符串压缩、LRU、repeat、图片懒加载、倒计时 Hook、事件循环输出题 |

**关键结论：手撕代码只占约 10%，全部 8 场加起来也就 9 道题，且都是「中等偏易 + 工程向」。**

也就是说，像 `buildTree` / `collectSubtreeIds` / `extractMentions` 这种**业务纯函数**，
面试基本不会让你现场写；面试官真正会追的是——

> "这个无限层级懒加载是纯前端还是结合后端？""实时同步冲突怎么解决的？"
> "为什么用 SSE 不用 WebSocket？""说说事件循环。"

所以「每天手敲一个业务纯函数」投入产出比很低：它既不是面试代码题，
讲的也大多不是面试官会问的点。

## 三、为什么项目还要做，但不用手敲

面经里项目问题占 30%，且**几乎全部都能从 Lotion 的代码里找到答案**：

| 面经问题 | 对应 Lotion 代码 |
|----------|------------------|
| 无限层级文件夹懒加载 | `lib/db.ts` `getSidebarAll()` + `document-list.tsx` |
| 实时同步 / 冲突 | Convex WebSocket 推送；冲突 → CRDT/OT（要能对比着讲） |
| 草稿及时恢复 | BlockNote `onChange` → 实时保存 |
| AI 事件流 | `lib/agent.ts` SSE 事件流、`onEvent` 回调上报副作用 |
| 权限隔离 | Supabase RLS（未发布文档被拦截） |
| 长会话上下文压缩 | `lib/compress.ts` 滑动窗口 + 摘要 |
| 性能优化 | 骨架屏 / 分页 / 局部状态 / 懒加载 |

你的任务不是"写出这些代码"，而是**能把每一行背后的取舍讲成 STAR**：
背景 → 痛点（N+1、全量同步、DOM 爆炸）→ 方案 → 对比替代方案 → 量化收益 → 踩过的坑。

## 四、每天怎么用

1. **A 轨**：我写好当天代码 → 你跑测试看行为 → 照着 `docs/讲稿/` 模板写 2 分钟口述稿 → 我扮演面试官追问。
2. **B 轨**：打开 `docs/B1-前端八股考点.md`，挑 3~5 条，**合上答案自己讲**，讲不出的标记出来。
3. **C 轨**：从手撕题库挑 1 道，**限时 20 分钟**手写，写完对照参考实现。
4. **收尾 5 分钟（简历对齐）**：挑 `docs/全轨-简历映射.md` 上的一条词，合上资料用三段式讲 2 分钟；讲不满的记进 `docs/日志/dayNN-全轨-日志.md`。

## 五、简历即考纲（v3 新增：题目是从你简历里长出来的）

> 在腾讯做 Agent 开发实习的朋友的原话：「重点就是你把项目吃透。他只会看着你简历问呀。
> 你所有涉及到的每一个技术栈、中间件，在你项目里怎么用、流程怎么样，都得吃透。然后 agent 开发就是 agent 八股。」

上面 8 场面经告诉你**考什么类型**（八股 ~60% / 项目深挖 ~30% / 手撕 ~10%）；
这句话告诉你**题从哪来**：不是从固定题库抽的，而是**顺着你简历上的字往下问**。
所以准备的单位要从「知识点」换成「**简历上的一个词**」。

### 四条铁律

1. **写了必须吃透，吃不透就删** —— 简历上写了 Zustand 却讲不出为什么不用 Redux，是负分，比不写还糟
2. 每个词按**三段式**准备：① 在我项目里干什么（一句话）→ ② 完整流程走一遍（谁调谁、数据从哪流到哪）→ ③ 为什么选它、不用 X
3. 八股**顺着技术栈问**：写了 SSE 就问为什么不用 WebSocket；写了 Supabase 就问它托管了什么
4. 第 ② 步才是分水岭 —— 面试官全靠它区分「用过」和「懂」

> 逐词映射表见 **`docs/全轨-简历映射.md`**：按简历上的词分组，标出「在我项目里 / 会被追什么 / 对应材料 Day」。

### 日常动作（不额外占时间，挂在已有轨道上）

| 频率 | 动作 | 挂在 |
|------|------|------|
| 每天 | A 轨结束前，挑简历上的一条，**合上资料讲 2 分钟**（三段式） | A 轨最后 5 分钟 |
| 每天 | B1 / B2 的「结合项目」题，**优先挑简历上出现过的词** | B1 / B2 题纸 Part 3 / Part 5 |
| 每周（复盘日） | 简历**逐条念一遍**，哪条讲不满 2 分钟 → 那次复盘的重点就是它 | Day 11 / 18 / 25 / 35 / 42 |
| 简历定稿时 | 出现却答不上来的词：**补上 或 从简历删掉**，不留着赌 | 冲刺期 Day 46-48 |

> ⚠️ `docs/全轨-简历映射.md` 里那张表是我按 Lotion 技术栈**先填的**。
> **你简历上的原话只有你有** —— 把简历（或草稿）发我，我按原话逐条对齐。
> 差一个词，准备深度就完全不同：简历写「用了 Zustand」和写「做过状态管理选型」是两种题面。
