# MyLotion 学习策略 v2

> 依据：`D:\Codex_Project\实习面试_by柴师姐` 里 8 场面经（B站 / CSIG / IEG / 快手一面 / 快手二面 / 携程 / 腾讯云智一面 / 腾讯云智二面）。
> 目标：**前端实习 offer**，Lotion/MyLotion 是简历上的主项目。

## 一、先看数据：面试到底考什么

把 8 场面经的题目（去重后）按类型粗分：

| 类型 | 占比 | 典型题 |
|------|------|--------|
| 前端 / 计算机八股 | ~60% | 事件循环、闭包、跨域、强缓存 + hash、cookies/localStorage、重绘重排、hooks 原理、Zustand 选型、JWT vs session、进程线程、SSR / FCP / LCP |
| 项目深挖 | ~30% | CRDT vs OT、SSE vs WebSocket、无限层级懒加载、权限设计、状态分区、性能优化、Convex、BlockNote |
| 手撕代码 | ~10% | 有效的括号、数组拍平、EventEmitter、字符串压缩、LRU、repeat、图片懒加载、倒计时 Hook、事件循环输出题 |

**关键结论：手撕代码只占约 10%，全部 8 场加起来也就 9 道题，且都是「中等偏易 + 工程向」。**

也就是说，像 `buildTree` / `collectSubtreeIds` / `extractMentions` 这种**业务纯函数**，
面试基本不会让你现场写；面试官真正会追的是——

> "这个无限层级懒加载是纯前端还是结合后端？""实时同步冲突怎么解决的？"
> "为什么用 SSE 不用 WebSocket？""说说事件循环。"

所以「每天手敲一个业务纯函数」投入产出比很低：它既不是面试代码题，
讲的也大多不是面试官会问的点。

## 二、策略调整：从「手敲代码」转向「讲得清楚 + 只练高频手撕」

保留 MyLotion（得有项目可讲），但**代码由我直接产出，你负责读懂 + 讲出来**。
时间重新分配到三条轨道：

| 轨道 | 占比 | 做什么 | 产出物 |
|------|------|--------|--------|
| **A · 讲项目** | 30% | 读实现 → 用面试话术讲 2 分钟 → 我按面经提问挑刺 | `docs/讲稿/dayN-*.md` |
| **B · 八股** | 50% | 按 `docs/面经考点.md` 清单自测（开口讲，不默写） | 打勾 + 记不住的回填讲稿 |
| **C · 手撕** | 20% | 只练面经出现过的 + 大厂高频，每题限时手写一遍 | `src/interview/*.ts` + 用例 |

时间示例（每天 3 小时）：A 50min / B 90min / C 40min。

## 三、为什么项目还要做，但不用手敲

面经里项目问题占 30%，且**几乎全部都能从 Lotion 的代码里找到答案**：

| 面经问题 | 对应 Lotion 代码 |
|----------|------------------|
| 无限层级文件夹懒加载 | `lib/db.ts` `getSidebarAll()` + `document-list.tsx` |
| 实时同步 / 冲突 | Convex WebSocket 推送；冲突 → CRDT/OT（要能对比着讲） |
| 草稿及时恢复 | BlockNote `onChange` → 实时保存 |
| AI 事件流 | `lib/agent.ts` SSE 事件流、`onEvent` 回调上报副作用 |
| 权限隔离 | Supabase RLS（未发布文档被拦截） |
| 长会话上下文压缩 | `lib/compress.ts` 滑动窗口 + 摘要 |
| 性能优化 | 骨架屏 / 分页 / 局部状态 / 懒加载 |

你的任务不是"写出这些代码"，而是**能把每一行背后的取舍讲成 STAR**：
背景 → 痛点（N+1、全量同步、DOM 爆炸）→ 方案 → 对比替代方案 → 量化收益 → 踩过的坑。

## 四、每天怎么用

1. **A 轨**：我写好当天代码 → 你跑测试看行为 → 照着 `docs/讲稿/` 模板写 2 分钟口述稿 → 我扮演面试官追问。
2. **B 轨**：打开 `docs/面经考点.md`，挑 3~5 条，**合上答案自己讲**，讲不出的标记出来。
3. **C 轨**：从手撕题库挑 1 道，**限时 20 分钟**手写，写完对照参考实现。
